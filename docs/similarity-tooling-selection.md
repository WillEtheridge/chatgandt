# Similarity Retrieval Tooling Selection

**Decision status:** Frozen
**Purpose:** Retrieve likely prompt/response neighbours for human-readable overlap review; never classify contamination automatically

## Constraints

The corpus will contain fewer than 500 short English records. The tooling should run locally on a laptop, be deterministic, permissively licensed, version/revision pinnable, inexpensive, and straightforward to explain. Retrieval quality matters more than index scalability.

## Lexical shortlist

| Option | Strength | Limitation | Decision |
| --- | --- | --- | --- |
| Python `difflib.SequenceMatcher` | No dependency; deterministic | Character-order similarity is weak for reordered phrases and token substitutions | Not selected |
| Word TF-IDF cosine | Explainable and useful across a corpus | Fit vocabulary and tokenisation become additional versioned state; weak on paraphrase | Not selected for this small review tool |
| RapidFuzz token ratio | Fast, deterministic, MIT licensed, handles reordered words and surface edits | Score has no semantic meaning and repeated/common tokens can look similar | Selected as retrieval signal |

The pinned implementation is RapidFuzz `3.14.5`, `rapidfuzz.fuzz.token_ratio`, applied to the frozen normalized text. It returns the top five records. There is deliberately no accept/reject threshold: a high RapidFuzz score only moves a pair into the review packet.

## Semantic shortlist

| Option | Strength | Limitation | Decision |
| --- | --- | --- | --- |
| `all-MiniLM-L6-v2` | Small 384-dimensional English sentence embeddings, local CPU use, permissive license, documented mean-pooling implementation | 256-wordpiece truncation; not a contamination classifier | Selected |
| Larger sentence-transformer encoder | Potentially better retrieval on subtle cases | More download, memory, latency, and little practical benefit for fewer than 500 records | Not selected |
| Hosted embedding API | Convenient and potentially strong | Network/cost dependency and provider/model version drift weaken reproducibility | Not selected |
| Bag-of-words/TF-IDF as the only semantic signal | Tiny and transparent | Does not retrieve differently worded paraphrases reliably | Retained only as an unselected lexical alternative |

The selected model is `sentence-transformers/all-MiniLM-L6-v2` at revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`, Apache-2.0. The repository uses the already pinned Transformers runtime rather than adding SentenceTransformers. It follows the documented attention-masked mean pooling of the final hidden state, L2 normalizes the 384-dimensional result, and ranks by cosine similarity.

## Proportionate implementation

No vector database or approximate-nearest-neighbour service is needed. At this corpus size, embeddings can be computed in batches and compared exhaustively. This makes the complete candidate set, model identity, scores, and tie ordering reproducible.

Production evidence is generated by `scripts/generate_semantic_evidence.py`. The generator builds one sorted, de-duplicated text inventory, embeds it with the exact pinned MiniLM revision, and derives every token diagnostic, cosine score, and rank from the canonical inputs. The aggregate validators run the same computation again and require exact equality with the stored record inventory. Artifact hashes and captured generator output provide provenance, but they are not substitutes for recomputation: synchronously editing scores, ranks, reviews, and hashes still fails.

MiniLM receives at most the first 256 wordpieces. The verifier records untruncated counts and proves the long supplied-text calibration case is truncated. Truncated items require complete-text manual review. This makes a real model limitation visible instead of implying that embedding similarity covered omitted content.

## Selection gate

The tooling is acceptable only if:

- exact identities and normalization tests pass;
- the pinned package/model identity loads;
- lexical and semantic calibration report expected-match recall at five;
- the long supplied-text diagnostic reports more than 256 wordpieces and truncation; and
- reviewers apply the frozen three-question rule rather than scores.

The calibration set is intentionally small and synthetic. Passing it shows that the retrieval path works as designed; it does not estimate real-world contamination-detection accuracy.
