# Adversarial Review of the Dataset Contamination Audit Specification

> **Historical review.** Its findings describe the superseded D-058 design.
> The useful lesson is retained; the reviewed machinery is no longer active.

- **Reviewed document:** `docs/dataset-contamination-audit-specification.md`
- **Review date:** 2026-07-16
- **Review type:** Single bounded pre-implementation adversarial pass
- **Verdict:** Amend before implementation

## Scope and method

This review compared the candidate specification with D-038, D-039, D-044, D-046, the frozen unseen and response-similarity protocols, the dataset source/lifecycle/authoring contracts, the split contract, and the actual structures and identities of the declared non-supervised sources. It inspected supervised file identities and structures only. It did not inspect supervised candidate content, inspect or create exact held-out prompts, run retrieval, generate embeddings, load a model, run the production audit, assign splits, or change any source record.

All explicitly declared non-supervised file SHA-256 values checked during this pass match the repository files. The batch-level supervised collection identities also agree with the production summary. That does not resolve the path-binding issue below.

## Critical findings

### C-01 — The declared commands cannot produce most required canonical artifacts

The required output set includes the source manifest, extracted-reference inventory, deterministic report, lexical neighbours, flags, withheld checks, replacement records when needed, summary, and Markdown report. The command surface gives write authority only to `generate_dataset_contamination_evidence.py --output .../semantic-evidence.json`; every verifier mode is explicitly read-only. No declared command deterministically creates the other machine-generated artifacts, and the specification simultaneously says the evidence generator may write only declared audit artifacts without defining which command invocation creates each one.

This prevents an implementation review from proving that the documented production sequence can produce the declared closed bundle. It also leaves unclear whether `flags.jsonl` is frozen by the same run as the exact, lexical, structural, and semantic evidence or assembled later, which would undermine the no-post-result-tuning rule.

**Required amendment:** Declare one canonical production build command, or an explicit ordered set of build commands, that writes every machine-generated artifact from frozen inputs into a new atomic audit directory. Specify which artifacts are human-authored inputs to finalization (`dispositions.jsonl` and attestations), which are generated, the no-overwrite/atomic behavior, and a final read-only verification command. The immutable flag-set identity must be generated in the production evidence step before disposition begins.

### C-02 — The replacement overlay cannot produce a dataset that the existing freeze contract can validate

The dataset lifecycle makes acceptance terminal. The existing authoring/freeze validator requires a complete candidate/event population with exactly 200 terminally accepted candidates and treats every other candidate as terminally rejected. An overlay that subtracts an accepted original does not alter its terminal workflow state. If the original remains in the complete lifecycle population, adding an accepted replacement yields more than 200 accepted candidates; if the original and its events are omitted from the input, the later freeze no longer validates the complete authoring history that the audit says must remain immutable.

The proposed overlay is therefore not merely a missing helper. It changes the meaning of the accepted set outside the frozen dataset contract, while the specification claims it will preserve the later lifecycle and split rules. No canonical location or production command is declared for replacement candidate/event files either.

**Required amendment:** Choose and predeclare one contract-valid representation before implementation. The clean options are either (a) version the dataset contract and schemas with an append-only, terminal supersession mechanism that every authoring, split, projection, rendering, and freeze validator understands, or (b) define a new dataset-version source population whose complete lifecycle contract unambiguously yields exactly 200 active accepted records while retaining the prior version as external audit evidence. Do not rely on an audit-only overlay that downstream validators ignore. Bind replacement candidate/event paths, schemas, identities, and commands, and require the ordinary freeze validator to pass on the resulting complete population.

## Material findings

### M-01 — The prohibited target-model source inventory is incomplete

The authoring boundary prohibits any output generated by the target base or adapted model, not only prompt-development output. The specification includes the Ollama preflight output and six development collections but omits the existing pinned-Qwen CUDA inference-harness responses at `artifacts/diagnostics/inference-harness-cuda/20260714T151316Z-0879c92d/responses.jsonl` (SHA-256 `3f1334e7be37dfc80045ff307bf1e4bf1a56caeb6b1fa4ab854c5146d19fd7c9`). Its paired prompt file also exists at the same location (SHA-256 `3e4590ca32441373f2b0d2fcd2e2b1284092cadee3c524ef1bc87cf400730881`). The preflight protocol separately says its disposable prompts must not be reused, but the candidate specification extracts only preflight `raw_output`, not its `prompt` fields.

**Required amendment:** Inventory every repository-resident target-base/adapted-model output existing before dataset authoring, including the inference-harness diagnostic, and include its prompt where the governing record says that prompt is ineligible for training reuse. Either include all such sources with fixed identities and field extractors or enumerate and justify a closed exclusion for non-semantic technical fixtures. Apply the same rule consistently to the preflight prompt fields.

### M-02 — Development prompt verification is impossible from some declared inputs

The specification says repeated development prompts inside run evidence will be verified against the frozen 20-prompt input and de-duplicated by prompt identity. The four local response files contain `prompt_id` but no prompt text or messages. Their sibling `prompts.jsonl` and manifest files are not declared or identity-bound. Consequently, the verifier can check an ID join but cannot prove which prompt text those local outputs answered. The formal run responses do embed messages, but the six collections do not share one structure.

**Required amendment:** Bind each run's manifest and prompt file, with SHA-256, record count, and a source-specific join/extractor contract; or narrow the claim to what can be proven from each response format. Require prompt ID, prompt text identity, prompt-asset identity, system ID, run ID, attempt/repeat identity, and raw-output hash checks appropriate to that collection.

### M-03 — The source/view comparison matrix is underdefined and contains an impossible full-supervision comparison

The specification states that response references compare with response and full-supervision views. A standalone `raw_output` response reference has no prompt portion, so it cannot be compared like-for-like with a candidate full-supervision view. Conversely, development prompts and their outputs are related records that can form an exchange view, but no such reference construction or join identity is defined. Mixed calibration records add further ambiguity: judge calibration may contain one response or labelled `a`/`b` responses, while response-similarity calibration contains a query and multiple references.

This ambiguity can materially change both scores and flags while still appearing to comply with the prose.

**Required amendment:** Add an exhaustive source-class × extracted-field × candidate-view × reference-view matrix. Compare prompt to prompt/scenario, response to complete response, and full supervision only to a source record that deterministically binds its own prompt and response. Define stable IDs for every nested calibration response and for every joined development exchange. State explicitly which comparisons are ineligible rather than applying a generic response-to-full-supervision rule.

### M-04 — Threshold-only review drops the frozen top-five collision workload without a validated substitute

D-039 and the frozen unseen protocol define exact matching followed by top-five lexical, semantic, and metadata retrieval with recorded semantic judgment; scores retrieve neighbours but do not decide contamination. The candidate specification retains top-five evidence but requires dispositions only for pairs crossing newly introduced absolute thresholds. Those thresholds are not part of the frozen Stage 3 rule, and the existing calibration proves target retrieval at rank five, not that all genuine collisions exceed `90/92/95` lexical or `0.82/0.86/0.88` cosine.

The result can be a false negative: a top-five close paraphrase or scenario duplicate below an absolute threshold receives no human judgment. Freezing the number before results prevents tuning but does not validate the reduction.

**Required amendment:** Either include the de-duplicated top-five lexical/semantic/metadata union in the disposition workload, preserving the frozen retrieval contract, or add a pre-production calibration specifically demonstrating that the proposed threshold reduction retains every labelled collision for every applicable view/source class. If thresholds remain, define how ties at rank five and collections with fewer than five references are handled. Do not describe below-threshold top-five pairs as reproducibility-only evidence unless the frozen rule is explicitly and validly amended.

### M-05 — The supervised input identities do not bind the 22 declared paths

The specification says every path must match its SHA-256, but supplies only one digest for the byte concatenation of eleven candidate files and one for eleven event files. It supplies no expected per-file identities and does not define a path-and-boundary-aware aggregate serialization. Direct byte concatenation cannot detect a changed partition boundary that preserves the same combined bytes, yet batch identity is substantive provenance and is used by the replacement ledger.

**Required amendment:** Freeze all 22 per-file SHA-256 values and counts, or define a canonical aggregate manifest that hashes each relative path, byte count, record count, and file digest in numeric batch order. Retain the current concatenated digests only as secondary collection identities.

### M-06 — The automatic withheld-metadata failure is not deterministic as written

Supervised records have no dedicated `withheld_domain` field. `topic` is a closed general-domain enum, while `user_goal`, `requested_task_or_artefact`, `scenario_summary`, and constraints are free text. Deciding that a domain identifier or display name is assigned "as the substantive topic, goal, artefact, or scenario" requires contextual judgment. The rule is therefore incompatible with the claim that it requires no semantic discretion, and it can automatically fail incidental or negated mentions that the withheld-domain section says must not decide a violation.

**Required amendment:** Make only an exact value in a dedicated controlled domain field an automatic failure, if such a field exists. For the current schema, treat lexicon/name occurrences in free-text metadata as flags and reserve failure for the complete-text substantive disposition. Keep structural contract failures automatic.

### M-07 — The withheld lexicon remains a post-specification decision-rule component

The document presents itself as the complete fixed method, but delegates the versioned high-recall lexicon to implementation without providing its path, contents, identity, token/phrase matching semantics, or expected synthetic cases. That lexicon directly determines the review workload, including terms whose ambiguity is specifically acknowledged.

**Required amendment:** Require a named canonical lexicon artifact and schema, define normalization, word-boundary and multiword matching, domain attribution, and versioned synthetic positive/negative fixtures, and freeze its digest at implementation review before any production content is processed. Record that digest in the source manifest and prohibit lexicon changes after production evidence creation.

### M-08 — Replacement rerun semantics and artifact generations are not closed

The output directory names only `v1`, but the sequence allows an initial production evidence set and a complete post-replacement rerun. It does not define generation IDs, immutable preservation of the first run, how old dispositions and flags bind to the failed original, or which artifacts the final summary treats as current. Reusing one directory risks overwriting the evidence that justified replacement.

**Required amendment:** Define immutable run generations beneath the audit version (for example, entry and post-replacement generations), each with its own manifest and complete artifact set. The replacement ledger must bind the decisive entry-generation flags/dispositions and the final summary must identify exactly one current generation while retaining all earlier generations unchanged.

## Minor findings

### m-01 — Worked-prompt agreement should use deterministic rendering, not an undefined semantic comparison

`config/prompts/five-shot-v3.json` stores the assembled prompt as one `content` string, not five structured examples. The instruction that implementation review prove the five "semantic worked examples" agree with the five structured source examples does not define a parser or equality rule.

**Recommended amendment:** Reuse the existing deterministic five-shot renderer/validator and require exact assembled-content equality to rendering from `worked-examples-v1.json`, plus the already pinned file identities. Do not add a second natural-language parser.

### m-02 — Several descriptive structural summaries lack canonical extractors

`title prefixes`, `method-opening tokens`, and `garnish openings` are listed as reportable corpus summaries, but prefix length, tokenization, punctuation behavior, and empty-garnish handling are not fixed. The structural signature's "sentence-opening token" is similarly ambiguous when a method string contains leading punctuation or multiple sentences.

**Recommended amendment:** Define each extractor with normalized token rules and fixed prefix lengths, or remove fields that are only decorative. Preserve exact amount/unit and component-frequency summaries that already have determinate definitions.

### m-03 — The source-use attestation overstates the held-out claim

The attestation is said to cover held-out materials even though exact held-out prompts do not yet exist and accessing any such source would abort the run. This is not evidence of content non-use; it is a process-state assertion.

**Recommended amendment:** Separate the claim into (a) named prohibited sources were not used as seeds/templates/signals and (b) exact held-out prompts did not exist or were not accessible during Stage 4, bound to the relevant stage records. Do not imply that absent material was inspected.

## Proportionality assessment

The bounded one-review/one-implementation-review structure is proportionate, and retaining one disposition per canonical flagged pair is auditable. The principal workload risk is not the Cartesian machine comparison but an unmeasured union of eight-word, structural-frequency, component, and absolute-threshold flags. The implementation review should report flag counts on synthetic fixtures only and prove pair de-duplication; it must not tune production rules after seeing candidate results. M-04 is the required protection against reducing workload by silently dropping frozen top-five semantic review.

No further specification review pass is recommended after the concrete amendments above are resolved. A single implementation review against synthetic fixtures, frozen source identities, extractor inventories, command behavior, and downstream freeze compatibility is sufficient.
